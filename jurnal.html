Bagian Ketiga: Perburuan Kesalahan

1. Analisis Kode Rusak 1

Kode Asli pada Foto:

<head>
<script>
function Sapa() {
    alert("Selamat datang");
}
</script>
</head>
<body onload="sapa();">
  • Temuan Kesalahan: Ada perbedaan huruf pada nama fungsi. Fungsi yang dibuat bernama Sapa() (pakai 'S' besar), sedangkan yang dipanggil di dalam tag body adalah sapa(); (pakai 's' kecil).
  • Perbaikan dan Hasil: Samakan hurufnya. Kita bisa mengubah pemanggilnya atau fungsi aslinya agar sama-sama menggunakan huruf kecil. 
    <head>
<script>
function sapa() {
    alert("Selamat datang");
}
</script>
</head>
<body onload="sapa();">
    Hasil Eksekusi: Saat halaman web dimuat ulang, layar akan langsung memunculkan pop-up alert bertuliskan "Selamat datang".
  • Penjelasan Penyebab: JavaScript itu punya sifat case-sensitive, artinya huruf besar dan huruf kecil itu dianggap beda secara mutlak. Jadi, kalau fungsinya dibuat dengan huruf kapital Sapa(), tapi pas dipanggil malah pakai huruf kecil sapa(), peramban atau browser bakal kebingungan karena merasa fungsi sapa() belum pernah didefinisikan sebelumnya. Pastikan penulisan namanya sama persis!

2. Analisis Kode Rusak 2

Kode Asli pada Foto:

function hitung() {
    var x = prompt("Angka pertama");
    var y = prompt("Angka kedua");
    alert("Jumlahnya " + x + y);
}
/* Pengguna mengetik 5 dan 3, tetapi yang muncul bukan 8. */
  • Temuan Kesalahan: Hasil input dari prompt() otomatis dibaca oleh sistem sebagai teks atau string, bukan angka numerik. Saat digabungkan dengan simbol +, sistem malah merangkai teksnya, bukan menambahkannya secara matematika.
  • Perbaikan dan Hasil: Kita harus mengubah tipe datanya dari teks menjadi angka terlebih dahulu menggunakan Number(). 
    function hitung() {
    var x = Number(prompt("Angka pertama"));
    var y = Number(prompt("Angka kedua"));
    var hasil = x + y;
    alert("Jumlahnya " + hasil);
}
    Hasil Eksekusi: Saat pengguna memasukkan angka 5 lalu 3, alert yang muncul sekarang sudah menampilkan logika hitungan yang benar, yaitu "Jumlahnya 8".
  • Penjelasan Penyebab: Fungsi prompt() itu ibaratnya selalu menangkap apa pun yang kita ketik sebagai sebuah teks. Dalam JavaScript, kalau teks bertemu teks lalu dihubungkan pakai tanda +, sistem cuma akan menempelkan kedua karakter tersebut alias string concatenation, sehingga teks "5" ditambah teks "3" jadinya "53". Agar bisa dihitung layaknya angka beneran, kita butuh mengonversi teks tersebut menjadi angka murni dengan bantuan fungsi Number().

3. Analisis Kode Rusak 3

Kode Asli pada Foto:

function cek(nilai) {
    if (nilai = 100) {
        alert("Nilai sempurna");
    } else {
        alert("Belum sempurna");
    }
}
/* cek(20) tetap mengatakan sempurna. */
  • Temuan Kesalahan: Menggunakan tanda sama dengan tunggal (=) di dalam tanda kurung kondisi if. Simbol = itu fungsinya untuk memasukkan atau menetapkan nilai, bukan untuk membandingkan kecocokan nilai.
  • Perbaikan dan Hasil: Ganti tanda sama dengan tunggal tersebut menjadi operator perbandingan kesetaraan, yaitu dua (==) atau tiga (===) tanda sama dengan. 
    function cek(nilai) {
    if (nilai === 100) {
        alert("Nilai sempurna");
    } else {
        alert("Belum sempurna");
    }
}
    Hasil Eksekusi: Saat fungsi dipanggil dengan perintah cek(20), peringatan yang muncul sudah mengevaluasi kondisi dengan benar, yaitu "Belum sempurna".
  • Penjelasan Penyebab: Kesalahan ketik satu karakter ini adalah hal yang paling sering bikin pusing pemula! Tanda = tunggal itu disebut assignment operator atau untuk memberi nilai. Jadi saat kode menjalankan if (nilai = 100), sistem tidak melakukan pengecekan, melainkan secara paksa mengubah isi variabel nilai menjadi 100 saat itu juga. Karena angka 100 dianggap bernilai truthy atau sah/benar, program selalu merasa kondisinya terpenuhi dan menjalankan blok "Nilai sempurna" berapapun angka masukan awalnya. Ingat ya, kalau mau membandingkan nilai, selalu biasakan pakai == atau ===.

Bagian Keempat: Refleksi

  1. Baris Tabel Telusur yang Meleset dan Pelajarannya:
    Tebakan saya meleset di baris 2 (c + b hasilnya 25) dan baris 3 (a nilainya tetap 2). Dari sini saya belajar kalau JavaScript itu suka otomatis mengubah angka jadi teks kalau ditambah pakai tanda + dengan data yang bentuknya teks. Terus, saat kita memasukkan variabel ke dalam sebuah fungsi, fungsi itu cuma meminjam salinan nilainya saja. Jadi, apapun yang diotak-atik di dalam fungsi tidak akan mengubah nilai asli variabel yang ada di luar fungsi tersebut.
  2. Kode Rusak yang Paling Sulit Ditemukan Penyebabnya:
    Kode Rusak 3 adalah yang paling bikin pusing dan bahaya. Cuma gara-gara kurang satu tanda sama dengan (= yang seharusnya ==), program tidak menampilkan pesan error sama sekali di layar console atau biasa disebut bug diam-diam. Kodenya tetap jalan mulus, tapi logikanya berantakan karena sistem menganggap angka 100 itu sebuah kebenaran yang sah, sehingga kondisi pengecekan selalu dianggap benar terus-menerus terlepas dari angka berapapun yang kita ketik.
  3. Perbedaan Fungsi dengan Alert dibandingkan Fungsi dengan Return:
    Berdasarkan kode yang saya buat sebelumnya:
    • Fungsi yang pakai alert itu cuma bertugas menampilkan kotak pesan pop-up saja. Setelah pesannya muncul, ya sudah selesai. Fungsi ini tidak menghasilkan nilai apa-apa yang bisa kita simpan atau kita hitung lagi nantinya.
    • Beda banget sama fungsi yang pakai perintah return. Fungsi ini berguna untuk "mengembalikan" hasil hitungan kepada kita. Keuntungannya, hasil hitungan ini bisa kita simpan ke dalam variabel, dipakai untuk hitungan matematika lain, atau digabungkan dengan kalimat lain di bagian program yang berbeda. Jadi sifatnya jauh lebih serbaguna dan bisa dipakai ulang.
  4. Pentingnya Pemeriksaan Data Langsung di Halaman Web (Client-Side Validation):
    Walaupun pemeriksaan data pakai JavaScript di peramban pengguna ini secara teori bisa diakali oleh orang jahil yang mematikan fitur JavaScript-nya, tapi cara ini tetap sangat penting dan wajib ada. Alasan utamanya adalah demi kenyamanan pengunjung web. Dengan cara ini, kalau ada isian formulir yang salah, pengunjung bisa langsung tahu detik itu juga tanpa perlu menunggu halaman memuat ulang (loading dari awal). Ini juga sangat membantu meringankan kerja server utama web kita. Jadi, ibaratnya ini adalah satpam di depan pintu yang menyortir tamu dengan cepat, sebelum nanti diperiksa lebih ketat dan aman lagi di dalam brankas server.
