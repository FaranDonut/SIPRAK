Catatan Eksplorasi Properti CSS

Berdasarkan NIM 2510514025, didapat N_EKSPLORASI = ((2+5) mod 3) + 5 = 6 properti CSS baru di luar materi kelas yang saya coba ulik sendiri.

1. border-radius (Status: Berhasil)

Nilai yang sempat saya coba: 0, 8px, 14px, sampai 50%

Fungsinya menurut pemahaman saya: Properti ini dipakai buat bikin sudut kotak jadi melengkung atau tumpul, jadi tampilannya nggak kaku serba siku-siku lancip.

Potongan kode yang dipakai:

.demo-radius-after {
    border-radius: 14px;
}

Hasil uji coba langsung:

Sebelum (Sudut Siku 0px)

Sudut Siku Lancip

Sesudah (border-radius: 14px)

Sudut Melengkung 14px

Hal yang bikin kaget: Waktu saya iseng kasih nilai 50% di elemen persegi panjang, bentuknya ternyata nggak jadi lingkaran bulat sempurna, melainkan lonjong oval kayak telur.

Pertanyaan yang masih bikin penasaran: Gimana cara paling praktis kalau mau bikin lengkungan sudut yang beda-beda di tiap pojokan cuma dalam satu baris deklarasi?

2. box-shadow (Status: Berhasil)

Nilai yang sempat saya coba: 5px 5px 10px rgba(0,0,0,0.4) dan inset 0 0 8px #000000

Fungsinya menurut pemahaman saya: Ngasih efek bayangan di belakang elemen kotak biar kelihatan punya kedalaman (3D) dan terkesan agak mengapung dari background.

Potongan kode yang dipakai:

.demo-shadow-after {
    box-shadow: 5px 5px 10px rgba(0, 0, 0, 0.4);
}

Hasil uji coba langsung:

Sebelum (Tanpa Bayangan)

Tampilan Datar (Flat)

Sesudah (box-shadow Aktif)

Efek Timbul 3D

Hal yang bikin kaget: Ternyata ada kata kunci inset yang bisa ngebalik arah bayangan ke sisi dalam kotak, jadi tampilannya kayak tombol yang lagi ditekan mendalam.

Pertanyaan yang masih bikin penasaran: Kalau kita pasang bayangan yang blur-nya super tebal, apakah itu bakal memengaruhi posisi dan alur elemen-elemen di sekitarnya?

3. transition (Status: Berhasil)

Nilai yang sempat saya coba: 0.3s, 0.8s, sampai 2s pada warna latar dan teks

Fungsinya menurut pemahaman saya: Buat bikin animasi perubahan warna jadi halus dan bertahap pas kursor diarahkan ke elemen, jadi nggak langsung jepret berubah kaku.

Potongan kode yang dipakai:

.demo-transition {
    transition: background-color 0.8s ease, color 0.8s ease;
}
.demo-transition:hover {
    background-color: var(--warna-aksen);
    color: #FFFFFF;
}

Hasil uji coba langsung (coba arahkan kursor ke tombol di bawah):

Sebelum (Tanpa Transisi - Hover Kaku)

Sentuh Saya (Instan / Kaku)

Sesudah (transition: 0.8s - Hover Halus)

Sentuh Saya (Animasi Lembut)

Hal yang bikin kaget: Properti transition ternyata wajib dipasang di selektor utama elemen, bukan di selektor :hover-nya. Kalau ditaruh di :hover, pas kursor mouse digeser keluar perubahannya bakal langsung putus kaku.

Pertanyaan yang masih bikin penasaran: Gimana caranya bikin animasi transisi berjalan terus-menerus tanpa harus nunggu disentuh kursor pengguna?

4. transform: scale() (Status: Berhasil)

Nilai yang sempat saya coba: scale(1.05), scale(1.08), dan scale(1.2)

Fungsinya menurut pemahaman saya: Buat nge-zoom atau memperbesar ukuran visual elemen secara mulus dari titik tengahnya tanpa dorong-dorong elemen tetangga di sebelahnya.

Potongan kode yang dipakai:

.demo-transform-after:hover {
    transform: scale(1.08);
}

Hasil uji coba langsung (coba arahkan kursor ke kotak di bawah):

Sebelum (Ukuran Standar Scale 1.0)

Ukuran Statis (Tetap)

Sesudah (Hover Zoom Scale 1.08)

Sentuh Saya (Zoom 8%)

Hal yang bikin kaget: Efek pembesaran scale() ini naiknya kayak di lapisan atas dokumen, jadi susunan grid atau tabel di sekitarnya sama sekali nggak kegeser atau berantakan.

Pertanyaan yang masih bikin penasaran: Kalau kita nge-scale gambar yang punya Image Map (<map>), apakah koordinat area kliknya bakal ikut membesar secara akurat?

5. position: absolute (Status: Percobaan Gagal & Diperbaiki)

Nilai yang sempat saya coba: position: absolute; top: 4px; right: 4px;

Fungsinya menurut pemahaman saya: Menempatkan elemen secara bebas dan presisi berdasarkan jarak koordinat dari elemen pembungkus terdekatnya.

Potongan kode pas percobaan gagal:

/* Kode awal yang gagal: Wadah lupa dikasih position relative */
.wadah-gagal {
    /* Wadah masih posisi static (default) */
}
.label-gagal {
    position: absolute;
    top: 4px;
    right: 4px; /* Malah kabur keluar wadah */
}

Hasil uji coba langsung:

Percobaan Gagal (Wadah Lupa Di-set Relative)

Wadah Induk (Static)

Badge Nyasar ke Pojok Luar

Setelah Diperbaiki (Wadah Diberi Relative)

Wadah Induk (Relative)

Badge Mengunci Rapi di Pojok

Cerita kendala & cara menyadarinya: Niat awal saya pengin bikin lencana (badge) nempel rapi di pojok kanan atas kartu biodata di profil. Tapi begitu dipasang position: absolute, badge-nya malah loncat nyasar ke pojok atas layar browser! Setelah nyari tahu soal konsep containing block, saya baru sadar kalau kotak pembungkusnya wajib dikasih position: relative sebagai jangkar patokan. Begitu wadahnya dipasang relative, baru posisinya ngunci dengan bener.

Hal yang bikin kaget: Elemen yang berposisi absolute bakal terus mencari induk ke atas sampai mentok ke tag <body> kalau nggak ketemu induk yang berposisi relative.

Pertanyaan yang masih bikin penasaran: Kapan situasi yang paling ideal buat pakai position: sticky dibanding gabungan relative dan absolute?

6. white-space: nowrap (Status: Percobaan Gagal / Dibatalkan)

Nilai yang sempat saya coba: white-space: nowrap; dan white-space: normal;

Fungsinya menurut pemahaman saya: Memaksa teks di dalam kotak buat terus lurus dalam satu baris tanpa mau turun (wrap) ke baris baru meskipun mentok batas lebar.

Potongan kode percobaan:

/* Kode yang bikin tampilan teks meluber */
.demo-nowrap-gagal {
    width: 160px;
    white-space: nowrap; /* Teks nabrak dan tembus garis */
}

Hasil uji coba langsung:

Percobaan Gagal (white-space: nowrap)

Label Formulir Pendaftaran Mahasiswa Baru UPNVJ
Teks meluber menembus garis batas kotak

Sesuai Harapan (white-space: normal)

Label Formulir Pendaftaran Mahasiswa Baru UPNVJ
Teks otomatis melipat rapi ke bawah

Cerita kendala & cara menyadarinya: Saya pengin teks judul label formulir selalu rapi dalam satu baris lurus simetris. Makanya saya iseng coba pasang white-space: nowrap. Tapi pas halaman dibuka di layar yang agak sempit, teksnya malah meluber keluar garis tabel dan numpuk di atas kolom input. Karena bikin tampilan layout berantakan dan nggak responsif, eksperimen ini resmi saya batalkan dari form utama.

Hal yang bikin kaget: white-space: nowrap bener-bener keras kepala mengabaikan batas lebar width wadah induknya.

Pertanyaan yang masih bikin penasaran: Apa perbedaan teknis mendalam antara overflow-wrap: break-word dan word-break: break-all saat memecah kata yang panjang tanpa spasi?

Penyelesaian 5 Tantangan Terarah

1. Baris tabel selang-seling tanpa atribut bgcolor

Kata kunci pencarian: CSS alternate table row color pseudo class

Solusi yang saya terapkan: Memakai pseudo-class urutan tr:nth-child(even) di berkas CSS eksternal biar baris nomor genap otomatis punya warna latar yang beda.

2. Menu navigasi berubah warna secara mulus

Kata kunci pencarian: CSS smooth hover background color transition duration

Solusi yang saya terapkan: Menambahkan properti transition: background-color 0.4s ease pada selektor .menu-tabel a agar perpindahan warnanya waktu di-hover terasa lembut.

3. Kotak biodata melengkung dan punya bayangan

Kata kunci pencarian: CSS rounded corners box shadow element

Solusi yang saya terapkan: Menggabungkan properti border-radius: 10px; dan box-shadow: 5px 5px 10px rgba(0,0,0,0.25); pada kartu biodata.

4. Garis tabel menyatu (nggak ganda)

Kata kunci pencarian: CSS table merge double border single line

Solusi yang saya terapkan: Memasang properti border-collapse: collapse; pada elemen table di CSS.

5. Foto galeri sedikit membesar waktu disentuh

Kata kunci pencarian: CSS image zoom on hover transform scale

Solusi yang saya terapkan: Memakai transform: scale(1.05); yang dikombinasikan dengan transition: transform 0.3s ease; pada keadaan .gambar-kegiatan:hover.

Refleksi Pribadi

  1. Perbandingan jumlah baris jadwal.html Tugas 2 vs Tugas 3:
    Pada Tugas 2, jadwal.html lebih panjang karena banyak pengaturan tampilan masih ditulis langsung pada elemen HTML. Pada Tugas 3, aturan tampilan dipindahkan ke gaya.css sehingga kode HTML menjadi lebih ringkas.
  2. Hal yang dulu memakan waktu:
    Membuat warna baris tabel selang-seling dulu harus dilakukan satu per satu. Setelah memakai CSS, saya cukup menggunakan tr:nth-child(even).
  3. Hal yang justru lebih membingungkan:
    Saya masih agak bingung dengan position, terutama perbedaan relative, absolute, dan fixed.
  4. Contoh inline style yang buruk:
    Di situs saya, inline style dipakai tepat satu kali pada daftar.html, yaitu style="font-style: italic;". Saya tidak menggunakannya di jurnal ini karena style membuat struktur HTML dan tampilan bercampur. Kalau banyak halaman memiliki style sendiri, perubahan tampilan akan lebih merepotkan.
  5. Pengalaman aturan CSS tidak berlaku:
    Saya pernah membuat class isoma pada HTML, tetapi CSS memakai selector .ishoma. Setelah diperiksa, ternyata penamaannya berbeda. Setelah class disamakan, aturan CSS kembali berjalan.
  6. Penerapan box model:
    Pada setiap kartu jurnal saya memakai padding: 16px, border: 1px solid, dan margin-bottom: 24px. Padding 16px dipakai supaya tulisan tidak menempel pada garis, border 1px dipakai untuk membatasi kartu, sedangkan margin-bottom 24px memberi jarak antar-kartu supaya lebih mudah dibaca.
