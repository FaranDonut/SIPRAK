Jurnal Praktikum & Tabel Telusur JavaScript (TP4)

Dokumentasi penelusuran alur kode JavaScript berbasis NIM 2510514025 (ANGKA_A = 2, ANGKA_B = 5).

1. Tabel Telusur (Analisis Prediksi vs Hasil Console)

Kode uji coba yang dianalisis:

var a = 2;
var b = 5;
var c = "" + a;

function ubah(x) {
    x = x + 1;
    return x;
}

var d = ubah(a);

console.log(1, a + b);
console.log(2, c + b);
console.log(3, a);
console.log(4, d);
console.log(5, ubah(b) + ubah(b));
console.log(6, typeof c);

Tabel Perbandingan Ramalan dan Hasil Sebenarnya
No Ramalan Saya Hasil Sebenarnya Penjelasan Analisis
1 7 7 Variabel a (angka 2) dan b (angka 5) dijumlahkan secara aritmatika biasa ($2 + 5 = 7$).
2 7 25 Meleset. Variabel c didefinisikan sebagai "" + a sehingga bertipe data string "2". Operator + melakukan penggabungan string (string concatenation), menghasilkan "25".
3 3 2 Meleset. Variabel primitif di JavaScript bersifat pass-by-value. Perubahan x = x + 1 di dalam fungsi ubah() hanya mengubah variabel lokal fungsi dan tidak memengaruhi nilai variabel global a.
4 3 3 Variabel d menampung nilai kembalian (return value) dari ubah(2), yaitu $2 + 1 = 3$.
5 12 12 Pemanggilan ubah(5) pertama menghasilkan 6, dan pemanggilan kedua juga menghasilkan 6. Keduanya adalah tipe angka sehingga dijumlahkan $6 + 6 = 12$.
6 string string Variabel c berisi teks "2", sehingga operator typeof c mengembalikan nilai "string".

2. Perburuan Kesalahan (Debugging Tiga Kode Rusak)

Kode Rusak 1: Case Sensitivity pada Penamaan Fungsi

Gejala: Pesan sapaan tidak pernah muncul saat halaman selesai dimuat.

Letak Kesalahan: Definisi fungsi menggunakan huruf besar function Sapa(), tetapi dipanggil dengan huruf kecil onload="sapa();".

Perbaikan: Samakan pemanggilan menjadi function sapa().

Status Console: Menampilkan pesan error Uncaught ReferenceError: sapa is not defined.

Kode Rusak 2: Konkatenasi String Akibat Nilai Kembalian prompt()

Gejala: Pengguna memasukkan angka 5 dan 3, tetapi dialog memunculkan "Jumlahnya 53".

Letak Kesalahan: Hasil dari prompt() bertipe teks (string), sehingga operator + menggabungkan teks alih-alih menjumlahkan angka.

Perbaikan: Konversi input ke angka dengan Number() atau parseInt(): var total = Number(x) + Number(y);

Status Console: Tidak memunculkan pesan error di console (silent logic error).

Kode Rusak 3: Kesalahan Operator Assignment pada Percabangan If

Gejala: Pemanggilan cek(20) tetap menghasilkan output "Nilai sempurna".

Letak Kesalahan: Menggunakan tanda sama dengan satu if (nilai = 100) yang merupakan penugasan nilai, bukan perbandingan.

Perbaikan: Gunakan operator perbandingan if (nilai == 100).

Status Console: Tidak memunculkan error sintaks karena penugasan di dalam if tetap valid secara sintaksis.

3. Refleksi Pribadi Praktikum JavaScript (TP4)

  1. Analisis Baris Tabel Telusur yang Meleset:
    Ramalan saya meleset pada baris kedua (c + b menghasilkan "25") dan baris ketiga (a tetap 2). Pelajaran penting yang saya dapatkan adalah bahwa JavaScript melakukan type coercion (penggabungan string) secara otomatis jika salah satu operan bertipe teks. Selain itu, variabel primitif yang dikirim ke parameter fungsi bersifat pass-by-value, sehingga perubahan variabel lokal di dalam fungsi tidak akan mengubah nilai variabel aslinya di luar fungsi.
  2. Kode Rusak yang Paling Sulit Ditemukan:
    Kode Rusak 3 (kesalahan operator assignment = pada if) adalah yang paling menjebak. Kode tersebut tidak memunculkan pesan error apapun di panel Console browser dan secara sintaks dianggap valid oleh JavaScript. Akibatnya, alur logika berjalan salah secara diam-diam (silent bug) karena kondisi selalu bernilai truthy.
  3. Perbedaan Fungsi dengan Alert vs Fungsi dengan Return:
    Fungsi seperti sapaPengunjung() menggunakan alert untuk berinteraksi langsung menampilkan pesan ke layar pengguna tanpa mengembalikan data. Sedangkan fungsi seperti totalSKS() dan cekNilai() menggunakan return murni untuk mengembalikan nilai hasil komputasi. Fungsi dengan return jauh lebih fleksibel dan modular karena hasil perhitungannya dapat disimpan dalam variabel, diolah lebih lanjut, atau ditampilkan dengan berbagai format tampilan lain.
  4. Urgensi Validasi di Sisi Klien (Client-Side Validation):
    Meskipun pemeriksaan pada validasiFormulir() dapat dilewati dengan mematikan JavaScript di peramban, validasi di sisi klien tetap sangat berguna sebagai garis pertahanan pertama (first line of defense). Fungsinya memberikan user experience (UX) yang cepat dan responsif karena pengguna langsung diberi tahu jika ada kolom yang salah ketik tanpa harus menunggu respons dari server, sehingga dapat menghemat bandwidth dan beban komputasi server.
