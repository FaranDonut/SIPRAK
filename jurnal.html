Bagian Ketiga: Perburuan Kesalahan

1. Analisis Kode Rusak 1

  • Gejala yang terlihat: Alert tidak muncul saat halaman dimuat ke peramban.
  • Letak barisnya: Deklarasi nama fungsi function Sapa() (berawalan huruf kapital) dan atribut pemanggil onload="sapa();" (berawalan huruf kecil).
  • Perbaikan yang dilakukan: Menyamakan penulisan nama fungsi menjadi konsisten berhuruf kecil: function sapa() { alert("Selamat datang"); }.
  • Penjelasan penyebab: JavaScript bersifat case-sensitive (membedakan huruf besar dan kecil secara mutlak). Browser mencari fungsi sapa() yang belum didefinisikan.
  • Pesan pada Console: Menghasilkan galat merah: Uncaught ReferenceError: sapa is not defined.

2. Analisis Kode Rusak 2

  • Gejala yang terlihat: Ketika pengguna memasukkan angka 5 dan 3, pesan alert menampilkan "Jumlahnya 53", bukannya 8.
  • Letak barisnya: Baris pembacaan input prompt() dan baris penjumlahan teks alert("Jumlahnya " + x + y);.
  • Perbaikan yang dilakukan: Melakukan konversi eksplisit nilai kembalian prompt menjadi angka numerik dengan Number(): 
    function hitung() {
    var x = Number(prompt("Angka pertama"));
    var y = Number(prompt("Angka kedua"));
    var total = x + y;
    alert("Jumlahnya " + total);
}
  • Penjelasan penyebab: Fungsi bawaan prompt() selalu mengembalikan tipe data string. Operator + antara dua string melakukan penggabungan string (string concatenation), sehingga "5" + "3" menghasilkan "53".
  • Pesan pada Console: Tidak memunculkan pesan error apapun (silent logic error).

3. Analisis Kode Rusak 3

  • Gejala yang terlihat: Saat fungsi dipanggil dengan cek(20), sistem tetap menampilkan "Nilai sempurna".
  • Letak barisnya: Baris kondisi percabangan if (nilai = 100).
  • Perbaikan yang dilakukan: Mengganti operator penugasan tunggal (=) menjadi operator perbandingan kesetaraan (=== atau ==): if (nilai === 100).
  • Penjelasan penyebab: Simbol = adalah operator penugasan (assignment). Sintaks nilai = 100 mengubah isi variabel menjadi 100, lalu angka 100 dievaluasi sebagai nilai truthy, sehingga blok kode if selalu dijalankan terlepas dari nilai masukan awal.
  • Pesan pada Console: Tidak memunculkan pesan error sama sekali karena penugasan di dalam ekspresi if secara sintaksis tetap sah.

Bagian Keempat: Refleksi

  1. Baris Tabel Telusur yang Meleset & Pelajarannya:
    Ramalan saya meleset pada baris 2 (c + b menghasilkan 25) dan baris 3 (a tetap 2). Pelajaran penting yang saya peroleh adalah bahwa JavaScript secara otomatis mengubah tipe data menjadi string saat operator + menemukan operand berupa teks. Selain itu, passing parameter untuk tipe data primitif bersifat pass-by-value (menyalin nilai), sehingga manipulasi nilai pada variabel fungsi lokal tidak akan mengubah variabel di lingkup global/luar.
  2. Kode Rusak yang Paling Sulit Ditemukan Penyebabnya:
    Kode Rusak 3 adalah yang paling berbahaya dan sulit ditemukan. Kesalahan penulisan satu tanda sama dengan (= alih-alih ==) tidak memicu galat sintaks di Console peramban (silent bug). Secara logika program berjalan lancar, namun seluruh percabangan selalu masuk ke kondisi benar akibat sifat nilai truthy pada angka selain nol.
  3. Perbedaan Fungsi dengan Alert vs Fungsi dengan Return:
    Berdasarkan implementasi kode saya pada Bagian D:
    • Fungsi sapaPengunjung() hanya menjalankan aksi (prosedur) berupa dialog popup melalui alert, tanpa memberikan nilai kembali (mengembalikan undefined) sehingga nilainya tidak dapat diolah kembali.
    • Sebaliknya, fungsi totalSKS() dan cekNilai() menggunakan return untuk mengirimkan hasil kalkulasi numerik dan string kembali ke pemanggilnya. Nilai tersebut bersifat modular, bersih dari efek samping (side-effects), dan dapat diolah kembali, dirangkai menjadi teks lain, atau diuji secara otomatis.
  4. Urgensi Pemeriksaan di Sisi Klien (Client-Side Validation):
    Meskipun validasi sisi klien dapat dilewati dengan menonaktifkan JavaScript atau melalui rekayasa jaringan, validasi di sisi klien tetap sangat penting dan wajib diterapkan. Fungsi utamanya adalah memaksimalkan kenyamanan pengguna (User Experience/UX) dengan memberikan umpan balik seketika tanpa jeda pemuatan ulang halaman (page reload), serta menghemat kuota lalu lintas jaringan (bandwidth) dan beban server. Validasi klien bertindak sebagai lini pertahanan pertama bagi pengguna, sementara validasi sisi server (server-side validation) tetap bertindak sebagai garda keamanan mutlak.
