Bagian Ketiga: Perburuan Kesalahan

1. Analisis Kode Rusak 1

  • Gejala yang terlihat: Peringatan alert tidak pernah muncul saat halaman web dimuat.
  • Letak barisnya: Pada baris definisi fungsi function Sapa() dan baris pemanggil onload="sapa();".
  • Perbaikan yang dilakukan: Menyamakan nama fungsi menjadi huruf kecil: function sapa() { ... }.
  • Penjelasan penyebab: JavaScript bersifat case-sensitive. Pemanggilan sapa() mencari fungsi berhuruf kecil yang belum terdefinisi.
  • Pesan pada Console: Muncul error merah Uncaught ReferenceError: sapa is not defined.

2. Analisis Kode Rusak 2

  • Gejala yang terlihat: Input angka 5 dan 3 menghasilkan alert "Jumlahnya 53", bukan 8.
  • Letak barisnya: Baris alert("Jumlahnya " + x + y); dan pembacaan prompt.
  • Perbaikan yang dilakukan: Mengubah input teks menjadi angka menggunakan Number(): 
    var x = Number(prompt("Angka pertama"));
var y = Number(prompt("Angka kedua"));
var total = x + y;
alert("Jumlahnya " + total);
  • Penjelasan penyebab: Fungsi prompt() selalu mengembalikan tipe data string. Operator + pada string melakukan penggabungan teks ("5" + "3" = "53").
  • Pesan pada Console: Tidak memunculkan pesan error apapun di Console (*silent logic error*).

3. Analisis Kode Rusak 3

  • Gejala yang terlihat: Pemanggilan cek(20) tetap menampilkan "Nilai sempurna".
  • Letak barisnya: Baris kondisi if (nilai = 100).
  • Perbaikan yang dilakukan: Mengganti operator penugasan menjadi operator pembanding: if (nilai == 100).
  • Penjelasan penyebab: Tanda sama dengan satu (=) adalah penugasan (*assignment*). Pernyataan nilai = 100 mengubah nilai menjadi 100, yang dievaluasi sebagai kondisi benar (*truthy*), sehingga blok if selalu dijalankan.
  • Pesan pada Console: Tidak memunculkan pesan error di Console karena secara sintaks penugasan di dalam if tetap sah.

Bagian Keempat: Refleksi

  1. Baris Tabel Telusur yang Meleset & Pelajarannya:
    Ramalan saya meleset pada baris 2 (c + b menghasilkan 25) dan baris 3 (a tetap bernilai 2). Pelajaran penting yang saya peroleh adalah bahwa JavaScript secara otomatis melakukan konversi tipe data ke string (*type coercion*) ketika operator + bertemu dengan data teks. Selain itu, saya memahami bahwa passing parameter primitif ke dalam fungsi bersifat pass-by-value, sehingga modifikasi parameter lokal di dalam fungsi tidak memengaruhi variabel aslinya di luar fungsi.
  2. Kode Rusak yang Paling Sulit Ditemukan Penyebabnya:
    Kode Rusak 3 adalah yang paling sulit ditemukan. Hal ini karena penulisan if (nilai = 100) tidak menghasilkan pesan error sama sekali di panel Console (*silent bug*). Jika hanya membaca kode sepintas, tanda sama dengan satu terlihat sangat mirip dengan pembanding kesamaan, padahal fungsinya justru mengubah nilai variabel dan selalu bernilai *true*.
  3. Perbedaan Fungsi dengan Alert vs Fungsi dengan Return:
    Fungsi sapaPengunjung() menggunakan alert untuk menampilkan pesan langsung ke pengguna tanpa menghasilkan nilai yang bisa diolah lagi (bersifat prosedur/aksi langsung). Sebaliknya, fungsi totalSKS() dan cekNilai() menggunakan return untuk mengembalikan data hasil kalkulasi murni. Nilai kembalian tersebut dapat disimpan ke variabel lain, digabungkan dengan teks lain, atau diuji lebih lanjut sebelum ditampilkan kepada pengguna.
  4. Urgensi Pemeriksaan di Sisi Klien (Client-Side Validation):
    Pemeriksaan di sisi klien tetap sangat berguna dan penting terutama untuk *User Experience* (UX). Validasi JavaScript langsung memberi tahu pengguna seketika bila ada kesalahan input (seperti nama kosong atau panjang NIM yang tidak tepat) tanpa perlu memuat ulang halaman atau membuang lalu lintas jaringan (*bandwidth*) ke server. Meskipun validasi sisi server tetap wajib demi keamanan akhir, validasi sisi klien bertindak sebagai lini pertahanan pertama yang efisien dan responsif bagi pengguna.
